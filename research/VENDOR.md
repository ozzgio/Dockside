# USB Display interoperability research

This is an initial read-only investigation of the user's own Cabletime ScreenDock and its bundled driver. Dockside 1.2 remains a companion dashboard. **No replacement driver has been implemented.**

## Observed

- USB Display 1.1 (build 22), bundle identifier `com.winnerwave.USBDisplay`.
- Signed by WINNER WAVE TW LIMITED, Team ID `U3ZKT8QDTJ`; the inspected copy passes strict signature verification and macOS Gatekeeper accepted the supplied app as notarized.
- Universal Intel/Apple Silicon executable. Inspected executable SHA-256: `1f3a44f9b7ad79f85f7ef6cdc03f514d89ec5384d8c4e2f2805e724f63baf182`.
- USB device product name `Actions_MAC`, VID `0x1DE1` (7649), PID `0xF201` (61953). The vendor app's bundled configuration matches those IDs.
- The app exposes the panel through a virtual display named `HDMI Extender (HDMI 1)`. Its logs show a 1280 × 720 video stream. The Mac originally offered a 1920 × 1080 virtual desktop; selecting 1280 × 720 avoids that additional downscaling.
- Binary names include `AMUSBDevice`, `AMHIDDevice`, `MirrorSession`, `H264Encoder`, `EZVirtualDisplay`, `VirtualDisplayFactory`, `sendH264Data`, `sendBulkCommand`, and `writeBulkData`.
- Imported functions include `CGDisplayStreamCreateWithDispatchQueue` and `IOHIDDeviceSetReport`. The app links VideoToolbox, IOKit, IOSurface, and Metal.
- The bundled configuration has `host-control-ui-enabled = false`; there is no working brightness command exposed by Dockside. The current keep-awake feature is a macOS power assertion, not panel brightness.

## Inference

The names and imports are consistent with a pipeline that creates a virtual display, captures frames, encodes H.264, and sends video plus control traffic over USB/HID. They do **not** establish the session handshake, packet framing, endpoint layout, or brightness command. A native replacement must independently implement and verify those parts.

The distinction matters: removing the vendor process removes the software display/transport path. Keeping a dashboard window open cannot send pixels to the panel by itself. The firmware's USB Display setup graphic is generated by the device, not by Dockside.

## Next bounded experiment

1. Inventory the interfaces and endpoint descriptors for only VID/PID `1DE1:F201`, without claiming/opening interfaces.
2. Identify how a normal streaming session starts and stops, using a synthetic clock window. Keep any raw captures local because encoded frames may contain desktop content.
3. Determine the smallest video-frame envelope and acknowledge/control messages. Record exact evidence and unknown fields; do not transmit guessed packets.
4. Only after that is understood, build a separate minimal test sender. Validate it with the vendor process fully stopped and the original app available for recovery.

No firmware flashing, undocumented brightness writes, signature patching, or system-security changes are needed for this investigation. Vendor binaries and decompiled code are excluded from this repository.

Run `zsh research/inspect-vendor.sh` to reproduce the sanitized inventory. The associated project skill is `.cursor/skills/vendor-display-research/SKILL.md`.
